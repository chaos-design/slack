01从 Prompt 到 Process

Core Idea

早期 AI 生产力工作流很简单：写一个 prompt，得到答案，再把答案复制到有用的位置。

Principles
  • 但凡任务需要多步骤、真实环境反馈或迭代式打磨，单次提示就会很快失效。
  • Loop engineering 设计的是会行动、观察结果、决定下一步并重复执行直到目标达成的系统。
Source Basis

Early AI productivity workflows were simple: write a prompt, get an answer, copy it somewhere useful.

For anything that requires multiple steps, real-world feedback, or iterative refinement, single-shot prompting falls apart fast.

02Loop 与 Chain 的区别

Core Idea

Chain 是线性的：步骤 A 接步骤 B，再接步骤 C。

Principles
  • Loop 是动态的：Agent 可以发现某一步不奏效，改换策略重试，然后再继续。
  • 循环会持续到任务完成、停止条件触发，或 Agent 判断无法继续推进为止。
Source Basis

A chain is linear: step A leads to step B leads to step C.

A loop is dynamic: the agent can discover that an approach did not work, retry with a modified approach, and only then move on.

03ReAct 与编码循环

Core Idea

ReAct 模式把推理步骤与行动步骤交替组织。

Principles
  • 在代码生成中，Agent 会理解目标、写代码、运行代码、观察输出或错误、分析问题并修正。
  • 这种 reason、act、observe、repeat 的循环，就是 loop engineering 的核心。
Source Basis

The ReAct pattern interleaves reasoning steps with action steps.

In code generation, the agent understands the goal, writes code, runs it, observes output or errors, reasons about what went wrong, and revises.

04可靠 loop 的五个部件

Core Idea

循环需要清晰目标，知道什么状态才算完成。

Principles
  • Agent 需要代码执行、文件访问、终端命令、搜索、文档查询和测试运行器等工具。
  • 循环还需要上下文管理、终止逻辑和错误处理，避免上下文爆炸、无限运行和重复失败。
Source Basis

The loop needs a clear goal or task definition so it knows what done looks like.

The agent needs tools such as code execution, file access, terminal commands, search, documentation lookup, and test runners.

05Coding Agent 的质量差异

Core Idea

AI coding agents 的质量差异通常不在基础模型，而在 loop 设计。

Principles
  • 好的 Agent 会读取完整错误、记住历史尝试、控制任务范围，并验证结果确实可用。

From Prompt to Process · 从提示到过程

Loop engineering replaces manual prompting with goal-based automation. Early AI productivity workflows were simple: write a prompt, get an answer, and copy it somewhere useful. For tasks requiring multiple steps, real-world feedback, or iterative refinement, single-shot prompting falls apart.

Loop engineering 用目标驱动自动化替代手工提示。早期 AI 生产力流程很简单：写一个提示，得到一个答案，再把它复制到有用的地方。但对需要多步骤、真实世界反馈或迭代打磨的任务来说，一次性提示很快会失效。

Loop engineering is the shift from prompt to process. It designs agents that act, observe feedback, decide what to do next, and continue until a goal is reached.

Loop engineering 是从 prompt 转向 process 的变化。它设计的 Agent 会行动、观察反馈、决定下一步，并持续推进直到目标达成。

What Is a Loop · 什么是循环

A loop in agentic AI is a repeating cycle where the model takes an action, receives feedback from the environment, and uses that feedback to decide its next move. The loop continues until a termination condition is met: the task is complete, a stopping criterion triggers, or the agent determines it cannot go further.

在 agentic AI 中，loop 是一个重复循环：模型采取行动，从环境接收反馈，并用这些反馈决定下一步。循环会持续到满足 termination condition：任务完成、stopping criterion 被触发，或 Agent 判断无法继续。

A chain is linear: step A leads to step B leads to step C. A loop is dynamic: the agent can try step A, move to step B, discover B failed, retry with a modified approach, and only then continue.

Chain 是线性的：步骤 A 接步骤 B，再接步骤 C。Loop 是动态的：Agent 可以尝试 A、进入 B、发现 B 失败，用 modified approach 重试，然后才继续。

ReAct Pattern · ReAct 模式

Most modern agent loops trace back to the ReAct pattern, meaning Reason + Act, introduced in research from Princeton and Google. The core idea is to interleave reasoning steps with action steps.

大多数现代 Agent loops 可追溯到 ReAct pattern，也就是 Reason + Act，源自 Princeton 和 Google 的研究。核心思想是把 reasoning steps 与 action steps 交错组织。

In code generation contexts, this looks like: understand the goal, write some code, run the code and observe the output or error, reason about what went wrong, revise and re-run, and repeat until tests pass or the task is complete.

在 code generation 场景中，这表现为：理解目标、写代码、运行代码并 observe 输出或错误、推理哪里出了问题、修改并重跑，直到测试通过或任务完成。

Why Coding Needs Loops · 为什么编码更需要循环

Coding is naturally iterative. AI coding agents that skip this cycle and generate code once are limited. They cannot catch runtime errors, adapt to environment-specific issues, or verify that their output actually works.

编码天然是迭代式的。跳过这个循环、只生成一次代码的 AI coding agents 能力有限：它们无法捕捉 runtime errors，无法适应 environment-specific issues，也无法验证输出真的可用。

Loop engineering closes that feedback gap.

Loop engineering 关闭了这个 feedback gap。

Anatomy of a Well-Engineered Loop · 可靠循环的结构

A poorly designed loop wastes tokens, runs forever, or hallucinates progress. A well-designed loop is efficient, terminates correctly, and produces reliable output.

设计糟糕的 loop 会浪费 token、无限运行，或 hallucinates progress。设计良好的 loop 高效、能正确终止，并产出可靠结果。

The loop needs a clear goal or task definition. The goal definition should be specific enough to evaluate, broken into testable sub-tasks where possible, and scoped so the agent does not over-reach.

Loop 需要清晰目标或 task definition。目标应足够具体、可以评估；条件允许时拆成 testable sub-tasks；并控制范围，避免 Agent over-reach。

Tools and Context · 工具与上下文

Each loop iteration generates more context: code written, errors encountered, and decisions made. Without careful management, the agent will hit token limits or lose track of previous attempts.

每次 loop 迭代都会生成更多上下文：写过的代码、遇到的错误和做过的决策。若管理不当，Agent 会触达 token limits，或忘记之前的尝试。

For coding agents, the tool set typically means code execution, file system access, terminal/shell commands, search or documentation lookup, and test runners.

对 coding agents 来说，工具集通常包括 code execution、file system access、terminal/shell 命令、搜索或文档查询，以及 test runners。

Good loop engineering includes context management: summarizing previous iterations into compact working memory, keeping a structured log of attempted approaches and outcomes, and pruning irrelevant context before each new iteration.

好的 loop engineering 包含 context management：把之前迭代总结成紧凑 working memory，维护 attempted approaches and outcomes 的 structured log，并在每次新迭代前 pruning 无关上下文。

Termination and Recovery · 终止与恢复

A loop needs termination logic. This includes success conditions, failure conditions, and escalation paths: hand off to a human or another agent when stuck.

Loop 需要 termination logic，包括 success conditions、failure conditions，以及 escalation paths：卡住时移交给人类或另一个 Agent。

The agent should distinguish recoverable errors, such as syntax errors or missing imports, from hard blockers, such as missing credentials. It should adjust its strategy based on error type.

Agent 应区分可恢复错误，例如 syntax errors 或 missing imports，以及 hard blockers，例如缺少凭证。它应该根据错误类型调整 strategy。

Coding Agents and Multi-Agent Loops · 编码 Agent 与多 Agent 循环

Tools such as Claude Code, Devin, and OpenAI's Codex Agent rely on loop engineering as their core operating model. The quality difference is often not the base model, but the loop design.

Claude Code、Devin 和 OpenAI 的 Codex Agent 等工具都把 loop engineering 作为核心运行模型。质量差异通常不在 base model，而在 loop design。

Some tasks benefit from multiple agents running in coordinated loops: a planning agent breaks a large task into subtasks, executor agents handle subtasks in parallel, and a reviewer agent checks outputs and routes failures back for correction.

有些任务适合 multiple agents running in coordinated loops：planning agent 拆解大任务，executor agents 并行处理子任务，reviewer agent 检查输出并把失败路由回去修正。

Good coding agents handle errors by reading the full stack trace rather than making generic fixes, and verify output by confirming that a solution works, not just compiles.

好的 coding agents 处理错误时会读取完整 stack trace，而不是做泛泛修复；它们还会 verify output，确认方案确实可用，而不只是能编译。

Loop Patterns · 常见循环模式

The Retry Loop tries something, checks if it worked, and retries if it did not. The Plan-Execute-Verify Loop first generates a plan, executes it step by step, and verifies each step before proceeding.

Retry Loop 会尝试、检查是否有效，失败则重试。Plan-Execute-Verify Loop 会先生成计划，逐步执行，并在继续前验证每一步。

The Explore-Narrow Loop explores multiple solution paths, then narrows to the most promising one. The Human-in-the-Loop runs until it needs clarification or hits ambiguity, pauses for human input, then continues.

Explore-Narrow Loop 会探索多个方案路径，再收敛到最有希望的方案。Human-in-the-Loop 会运行到需要澄清或遇到歧义时暂停，获取人类输入后继续。

Practice · 实践建议

Define termination conditions before you start. Give the agent structured feedback, not just raw output. Log everything, summarize often, and set strict tool call budgets.

开始前先定义 termination conditions。给 Agent structured feedback，而不只是原始输出。记录所有行动，经常总结，并设置严格 tool call budgets。

Test your loops on failure cases, not just happy paths. Before deploying an agent loop, test it with ambiguous instructions, broken tools, bad data, long-running tasks, and partial failures.

要用 failure cases 测试 loops，而不只测 happy paths。部署 Agent loop 前，应测试模糊指令、工具损坏、坏数据、长任务和部分失败。
