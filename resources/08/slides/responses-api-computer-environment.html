正确结论：Responses API 的价值不只是新增 shell tool，而是把 shell、托管容器、文件系统、数据库、网络策略、skills 和 compaction 组合成生产级 Agent 工作流底座。
  • 单靠提示只能访问训练好的智能；计算环境让模型能操作文件、运行命令、调用 API 并生成持久产物。
  • Responses API 负责编排，shell 提供执行入口，container 提供状态与资源，skills 提供复用，compaction 支撑长任务。
  • 受控联网、allowlist、egress proxy 和域名级 secret 注入让能力扩展不等于无限制暴露。

结构速览

文章如何组织论证

01

问题不是命令行

Agent 落地需要中间文件、长表格、联网、重试和上下文管理等工程底座。

02

Shell 是执行入口

模型提出工具调用，平台在隔离环境执行，并把结果反馈回模型。

03

Loop 由 API 编排

Responses API 把模型上下文、工具执行、流式输出和后续推理串成闭环。

04

Container 是工作现场

文件系统、SQLite 和网络策略让 Agent 能组织资源，而不是把一切塞进 prompt。

05

Skills 降低重复摸索

重复流程被封装成可发现、可加载、可版本化的能力包。

06

Compaction 支撑长程

上下文压缩保留关键状态，让长任务跨多轮持续运行。

逻辑框架

从问题到方法的推进路径

01

提出问题

Agent 需要处理文件、API、网络、安全、重试和上下文等真实工程问题。

02

执行入口

shell tool 让模型能提出更广泛的计算机操作，但仍由平台实际执行。

03

编排闭环

Responses API 把模型、工具、输出和下一步推理组织成循环。

04

持久环境

容器提供文件、数据库和受控网络，成为 Agent 的工作现场。

05

复用能力

skills 把重复模式打包，减少每次重新规划的成本。

06

长程运行

compaction 保留关键状态，使长任务不因上下文膨胀而中断。

从模型回答到 Agent 工作流

By prompting models, you can only access trained intelligence.

The model proposes steps and commands; the platform runs them in an isolated environment.

所谓模型使用工具，实际上是模型提出工具调用。

When we say using a tool, the model actually only proposes a tool call.

We need an orchestrator to get model output, invoke tools, and pass the tool response back to the model in a loop.
